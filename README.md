# Wallpaper Engine Scene to MP4

[![Платформа](https://img.shields.io/badge/platform-Linux-informational?logo=linux)](https://www.kernel.org/)
[![Node.js](https://img.shields.io/badge/Node.js-required-339933?logo=nodedotjs&logoColor=white)](https://nodejs.org/)
[![Лицензия: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)

Хотели поставить красивые обои из Wallpaper Engine на Linux, например через [mpvpaper](https://github.com/GhostNaN/mpvpaper), но не нашли простого способа превратить требовательную интерактивную сцену в MP4? Этот проект создан именно для этого: он запускает сцену через движок Linux и записывает её в видео, которое затем можно использовать как обои.

После установки запустите утилиту одной командой — `node index.js`. В интерактивных подсказках укажите `.pkg`-архив и выберите длительность, и FPS записи. Утилита также умеет извлекать уже готовое видео из архива.

> **Экспериментальная версия.** Это первая версия проекта, она может работать нестабильно. Совместимость и успешный рендер всех сцен не гарантируются.

## Возможности

- Конвертирует интерактивные сцены Wallpaper Engine из `.pkg` в MP4 за один запуск утилиты.
- Позволяет выбрать длительность, разрешение и FPS ролика.
- Может извлечь готовое видео из архива.
- Показывает карту ресурсов архива: видео, текстуры, шейдеры, конфиги, аудио и прочее.

## Требования

- Linux.
- Node.js `>=14.14.0` и npm.
- `ffmpeg` и `xvfb-run` для стандартной записи сцены через Xvfb.
- `cage` и `wf-recorder` для экспериментального режима Cage headless.
- `git`, CMake, Make и системные библиотеки разработки для сборки движка, если он ещё не установлен.

Установщик проверяет зависимости и поддерживает автоматическую установку пакетов для следующих семейств дистрибутивов:

| Дистрибутивы | Пакетный менеджер |
| --- | --- |
| Ubuntu, Debian, Linux Mint, Pop!_OS | `apt` |
| Fedora, RHEL, CentOS, Rocky Linux, AlmaLinux | `dnf` |
| Arch Linux, Manjaro, EndeavourOS | `pacman` |

На других дистрибутивах установщик сообщит, что автоматическая установка не настроена. Необходимые зависимости в этом случае нужно установить вручную. на арч перед инсталлером нужно выполнить  sudo pacman -Syu

## Установка

1. Получите проект и перейдите в его каталог.
```bash
   git clone https://github.com/R31tr0/we-linux-to-mp4.git
   cd we-linux-to-mp4
   ```
2. Запустите установщик из каталога проекта:

   ```bash
   ./install.sh
   ```

   Если у файла нет права на запуск, используйте `chmod +x install.sh`.

3. Установщик проверит систему и спросит подтверждение перед установкой зависимостей. Для установки системных пакетов может потребоваться `sudo`.
4. При необходимости установщик установит npm-зависимости и соберёт `linux-wallpaperengine` из исходников.

Собранный исполняемый файл движка и сопутствующие файлы помещаются в `bin/` внутри каталога проекта. Каталог `bin/` создаётся при сборке и исключён из Git; повторный запуск установщика пропустит сборку, если исполняемый файл уже найден.

## Запуск

Из каталога проекта выполните:

```bash
node index.js
```

Это основной способ запуска; он не изменился. Если удобнее короткая команда, выполните в каталоге проекта `npm link` один раз, а затем запускайте `we-linux-to-mp4`.

Укажите путь к `.pkg`-архиву Wallpaper Engine. После анализа утилита покажет найденные ресурсы. Если в архиве есть готовые видеофайлы, можно выбрать один и извлечь его без рендера; иначе или при отказе от извлечения можно запустить рендер сцены.

При рендере скрипт спросит:

1. Длительность видео в секундах — положительное число.
2. FPS — положительное целое число; это значение передаётся и движку, и записи.
3. Способ рендера:
   - **Xvfb** (вариант по умолчанию) — сцена рендерится на CPU через llvmpipe; для записи нужны `xvfb-run` и `ffmpeg`.
   - **Cage headless** — экспериментальный режим с рендером на GPU через Wayland-композитор Cage и записью через `wf-recorder`; нужны оба пакета.
4. Разрешение — один из двух пресетов, только для Xvfb: `1920x1080` (по умолчанию) или `1280x720`. Меньший пресет обычно снижает нагрузку на CPU. В режиме Cage используется единое фиксированное разрешение `1920x1080`; выбрать другое нельзя.
5. Кодек: `libopenh264` (по умолчанию, CPU), NVIDIA `h264_nvenc` или AMD `h264_vaapi`. Аппаратные кодеки требуют подходящих GPU, драйверов и поддержки в установленном FFmpeg. Если выбранного кодека нет в FFmpeg, скрипт использует `libopenh264`.

- Извлечённое видео сохраняется в текущий каталог под именем из архива.
- Запись сцены сохраняется в текущий каталог под именем `output_scene_<random>.mp4`, где `<random>` — случайное число.

Для извлечения видео достаточно Node.js и npm-зависимостей проекта. Для рендера также нужен собранный движок. Результат и скорость зависят от выбранного способа рендера и кодека, мощности компьютера, драйверов и сложности сцены.

Если запись начинается с чёрного кадра, но обои появляются позже, попробуйте вручную увеличить задержку перед записью в `videoSupport.js`: `XVFB_START_DELAY` для Xvfb или `CAGE_START_DELAY` для Cage. Значения указаны в миллисекундах; например, `10000` означает 10 секунд. Это не исправит чёрный экран, вызванный несовместимостью сцены или ошибкой движка.

## Совместимость и ограничения

Рендер выполняется движком [`linux-wallpaperengine`](https://github.com/Almamu/linux-wallpaperengine), поэтому совместимость зависит от поддерживаемых им возможностей. Проект не заменяет этот движок и не гарантирует точное воспроизведение каждой сцены или работу на всех платформах.

### Проверенные дистрибутивы

| Дистрибутив | Статус |
| --- | --- |
| Fedora | Проверено |
| Ubuntu | Пока не проверено; ищу тестеров |
| Arch Linux | Пока не проверено; ищу тестеров |

Могут некорректно отображаться:

- сцены со сложными шейдерами;
- виджеты, например визуализаторы;
- эффекты, которые рендерятся отдельными слоями поверх основной сцены.

Новые шейдеры и виджеты, которые не поддерживаются используемой версией движка, работать не будут; возможны чёрные текстуры или чёрный экран. Для эффектов, вынесенных в отдельные слои, может понадобиться отдельно получить слои и склеить их самостоятельно.

Проект продолжает развиваться, но поддержка новых эффектов и возможностей зависит в том числе от самого `linux-wallpaperengine`.

ИИ использовался для помощи с разбиением проекта на модули и подбором параметров Wayland и FFmpeg; остальная работа — моя.

## Движок

Для рендера используется [`linux-wallpaperengine`](https://github.com/Almamu/linux-wallpaperengine). Установщик клонирует исходники этого проекта, собирает движок и копирует результаты сборки в `bin/` в каталоге данного проекта. Лицензия движка определяется его собственным репозиторием и не заменяется лицензией этого проекта.
